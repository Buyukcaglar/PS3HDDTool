DirectRequest now accepts optional SourceHashCache and SourceHashCacheSha256.
The CLI accepts corresponding --source-hash-cache and --source-hash-cache-sha256
flags. Both are required together; reuse requires a regular source image. The
loader validates the pinned cache checksum, inode metadata, node count, complete
directory topology and original tree digest. It then checks each file against its
saved hash while copying (including holes, partial final blocks and inline links).
A content mismatch aborts and follows the normal rollback path. Destination hash
verification remains mandatory. This avoids a separate full source pre-hash pass;
it does not skip source integrity checks or destination verification.

The new fields are omitted when null, preserving old journal checksums. The CLI
protects the cache from overlapping event-log or cancellation-file paths. A future
copy needs a NEW journal and fresh target qualification after re-preparation. The
old incomplete journal is historical evidence, not a restart request.

Identified bottleneck and fixes
------------------------------
The old writer performed a synchronous 16 KiB payload write and reread/rewrote a
whole 16 KiB indirect-pointer page for each 8-byte pointer update. Larger files
also reread parent pointer pages. Native counters showed 16 KiB writes, queue depth
around one and substantial target reads. No storage error was observed.

TreeTransfer now buffers contiguous payload writes in one reusable 1 MiB buffer.
Indirect pointer pages use a bounded, per-inode 16-page cache. Fresh pages begin
in memory, pages are written on eviction/completion, and buffers finish before
publishing the inode. Cancellation/error paths do not flush buffered data during
disposal. The existing journal write guard, native write-through flag, transaction
flushes, protected-data checks and clean-marker commit remain in force.
