# PS3HDDTool v1.4.0 — verified PS3 storage migration

This is the first public migration release of Buyukcaglar's fork, based on
Pheeeeenom/PS3HDDTool at 61cd041121529fb014a4637a99ad42315707c9bb.
It is published as the latest stable release, not a prerelease. The original
upstream license and contributor history are preserved.

## Added and fixed

- Guarded same-console PS3 tree migration to a differently sized, console-prepared
  target: native preflight, target preservation archive, durable metadata undo,
  full destination comparison and clean-marker commit.
- Native CBC192 byte swapping, explicit EID-root/derived keys, registry identity
  qualification, narrowly certified orphan recovery and non-UTF8 name preservation.
- Full headless CLI, NDJSON progress/heartbeats, structured errors and exit codes.
- Saved source hashes and verification-only pause/resume: no payload recopy or
  separate source payload rehash when resuming a valid verification checkpoint.
- Batched hashing/source reads, bounded indirect-page caching and up to 4 MiB
  output buffering; write-through and integrity/recovery checks remain enabled.
- Synthetic failure, recovery, CLI population and I/O comparison tests, operational
  documentation, privacy controls and the successful real migration case study.
- Override the inherited Tmds.DBus.Protocol dependency with the 0.21.3 security
  backport for [GHSA-xrw6-gwf8-vvr9](https://github.com/advisories/GHSA-xrw6-gwf8-vvr9).

## Validation and real execution

The development build passed 198 existing regressions, two additional large-write
rollback cases and populated 1 TB-to-2 TB CBC-bswap16 CLI stress (44,123 nodes;
2.61 GiB peak host storage). Public release validation is recorded in the included
evidence/release-validation.json. A real 1 TB image-to-2 TB SSD migration completed
on Evilnat CFW 4.93: 331,755 nodes and 830.36 GB logical contents checked, all
filesystem/protected-sector checks passed, clean commit and exit zero. The owner
reported successful initial use on the same console. This is one hardware case,
not a guarantee for all PS3 models/firmware/drives or every installed title.

The optimized destination verifier was used for that successful completion.
The later 4 MiB copy buffer was validated synthetically; its sustained real SSD
speedup has not been measured. Historical source hashes, real images and journals
remain private and are not release assets.

## Packages and operating limits

Windows x64 self-contained GUI and CLI ZIPs require no separately installed .NET
runtime. Corresponding source and SHA256 checksums are included. Building requires
the .NET 10 SDK. Physical migration requires Administrator privileges, a correctly
prepared offline target, exact fresh drive identity and matching console keys/users.
The GUI retains browsing/extraction; legacy GUI writes remain disabled. PS4 remains
read-only; Linux/macOS physical migration is not supported by this release.

Read README.md and docs/OPERATIONS.md before running writes. Keep independent
backups and the undo/archive evidence. Verification pause exits 131; copying
cancellation rolls back. Integrity failures can require recovery. Never reuse
an abandoned journal against a reformatted target.
