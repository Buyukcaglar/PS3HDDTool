Direct coverage
---------------
Success: plain, CBC-192 and XTS-128; full synthetic account/save/trophy/exdata/game/
vsh trees; existing-target replacement; metadata/UID/GID/timestamps/flags/generation;
case-sensitive/UTF-8 names; hard links; symlinks; sparse data; external attributes;
direct/single/double/triple pointers; lazy inode initialization and CG fallback.
An independent fixture/oracle checks raw inode/directory/payload/map/summary bytes;
the production verifier additionally compares the resulting tree with the source.

Protection: read-only planning causes no image/journal writes; source whole-file
hash remains unchanged; exclusive file leases reject conflicting opens; source
WriteBytes rejects writes; destination writes guarded by immutable original free
maps; protected old payloads and sectors outside the volume remain unchanged.

Faults: errors after dirty marker, during inode copy, after data flush, during
verification, and after clean commit all roll back. Cancellation rolls back.
Partial multi-sector primary-superblock and CG writes inject 512 bytes followed by
IOException, then exercise restoration using the same raw handle. Space/journal
budget and missing-registry refusal leave destination byte-identical.

Recovery: all three crypto modes recover with the source/key files unavailable;
repeat recovery is idempotent; copying restarts with a new journal afterward.
Ambiguous commit (clean sector written, complete state not saved) rolls back.
An interrupted rolling-back session can be retried.
Three real child processes call Environment.Exit(73), skipping catch/finally and
handle disposal, after the durable dirty marker, data copy and clean commit.
The parent reopens the destination and recovers the original tree in each case.
These tests exercise actual process termination, not physical power failure.

Corruption: corrupt undo, state checksum, changed file identity and modified
protected old payload are refused without additional destination writes.
Recomputed state checksums do not bypass missing-primary, payload-range, journal
budget or outside-volume-plan validation. Completed-session rollback and reusing
an existing journal directory are refused.

Original full-image coverage remains passing, including malformed UFS/geometry,
registry/key mismatches, inode/data capacity, unsupported/corrupt references,
publication failures and virtual >2^32-sector addressing. See VALIDATION.txt for
the earlier full-image-only run and its coverage details.
