Fix
---
Migration previously mapped cbc192 to unswapped CBC, while the verified native
CECHA00 disks use ciphertext pair swapping. New explicit mode cbc192-bswap16
selects the existing CBC wrapper with swapping enabled: swap ciphertext before
decrypting, encrypt then swap before writing, zero IV independently per sector.
Both request JSON and inline CLI arguments accept it. Legacy cbc192 semantics
remain unchanged. Source and destination modes and derived key bytes must match.
No autodetection/fallback or dirty/orphan/allocation exception was added.

An independent System.Security.Cryptography.Aes oracle checks raw ciphertext,
300-sector reads across the wrapper's chunk boundary, unaligned reads, ordinary
writes and full/partial pipelined encoding. The migration suite adds native-mode
package/direct/CLI sessions, process-loss recovery, and unchanged-input refusal
for dirty state, unclean flags, wrong/mixed modes and source/target orphan maps.
Generated keys are used exclusively. Existing UfsVolume safety checks are intact.
