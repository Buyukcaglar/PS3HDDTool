Explicit root-key input for migration CLI -- 2026-10-12
=====================================================

KeyKind="eid-root" on each ImageSpec/DirectEndpoint, or --key-kind eid-root for
inline requests, selects an exact48-byte EID root key in KeyFile. Existing ATA
seed derivation supplies24 bytes for the explicit CBC mode, or16+16 for XTS.
There is no mode/key-length autodetection, fallback or derived-key export.
Input/returned derivation buffers owned by the loader are zeroed after use.
The upstream derivation/cipher implementation still uses managed/internal copies;
this is not a claim of guaranteed complete process-memory erasure.

KeyKind omitted/null preserves derived-key behavior (CBC24/XTS32). Null properties
are omitted from serialized request/state JSON to retain legacy journal checksum
compatibility. KeyKind="derived" explicitly selects the existing format. Unknown
kinds, wrong lengths, root keys with plain mode and different derived HDD keys are
refused before journal creation or endpoint writes. Root/derived inputs can be
mixed only if their actual HDD keys compare equal in constant time.

No key bytes, key fingerprint or copied key files enter result/log/journal bundles.
Only existing host key paths and the selected kind are recorded. Source and target
remain restricted to the same explicitly selected encryption mode and console.
Destination-only recovery still reads raw ciphertext undo without any key/source.
Native offline/identity/alignment/write guards and preservation gates are unchanged.

Tests use GENERATED48-byte roots, an independent .NET AES seed oracle, generated
registries and small synthetic images only. No real drive or private key was used
by these tests. They cover legacy CBC/native CBC-bswap16/XTS; root-to-derived key
equivalence; target preservation/export; source immutability; independent output
oracle; wrong kinds/lengths/console keys; CLI parse and real child CLI capture/plan/
copy/verification; legacy JSON omission; no key export/secret bytes in journal; and
simulated process loss followed by recovery with root/derived/source unavailable.
