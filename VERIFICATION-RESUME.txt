Destination verification pause/resume (2026-10-13)

New builds save a checksummed verification-source-hashes.json in the journal
before modifying the destination. Each source file is checked while copying.
The journal enters verifying only after payload and allocation summaries are durable.

Ctrl+C or the cancellation marker during verifying now saves verification-paused.
The destination remains dirty and offline. The CLI emits terminal type paused,
exit 131, verificationPaused=true. This is not successful migration completion.
Cancellation during copying still rolls back. Integrity/I/O failures still attempt
rollback. A reporting error remains an error, even if verification was paused.

Restart full destination verification, then validate and commit:
  dotnet PS3HddTool.Migrate.dll direct-resume-verification --journal JOURNAL --json
    --event-log NEW_LOG --cancel-file NEW_UNUSED_MARKER

The event log must be new, outside the journal and protected inputs. Do not reuse
the previous cancellation marker. No payload is copied by this command.
Partial verification hashes are not durable; destination verification restarts at 0%.

Resume requires verification-paused or verifying, exclusive endpoint handles,
unchanged identities, a validated undo journal and protected target data, the
preservation archive when configured, matching source metadata/recovery evidence,
pinned source hashes/tree digest, and matching registry snapshots/bundles.
It does not hash source file payload again. It performs full destination hashing,
allocation/ownership/summary auditing, metadata/topology/hole/attribute comparison,
protected-sector comparison, then clean-marker commit with flush and readback.
Resume writes are constrained to the journal-backed clean-marker sectors.
Preflight rejection leaves the destination unchanged. Failure during resumed
verification attempts the same validated metadata rollback as direct-run.
direct-recover remains available for explicit rollback of a paused session.

Legacy verifying checkpoints may use the already pinned SourceHashCache when
their request contains one. No cache is guessed, generated by rehashing, or trusted
without matching its checksum and the journal SourceDigest. Other legacy phases
cannot be resumed by this command. State files must never be manually edited to
pretend that copying completed.

Hashing now traverses indirect pages once and merges contiguous logical/physical
data into reads of at most 1 MiB. Sparse holes and inline/partial tails retain their
exact logical hash semantics. This does not weaken any content or allocation check.

Deployment boundary: the active migration session
process uses a frozen older executable. It still rolls back on cancellation.
These source/build changes do not modify its executable, request, journal, or
behavior. Do not cancel/kill that process based on the new CLI behavior. A separate
authorized and tested transition is required before adopting a newer executable
for that live session. Existing monitors must treat exit 131 / terminal paused as
an incomplete, offline session needing an explicit resume or rollback decision;
they must never start another copy or report success.
